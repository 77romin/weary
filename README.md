# !WEARy

> 옷을 산 순간부터 입은 날들, 그리고 다음 주인에게 보내는 순간까지.

**WEARy**는 내 옷을 중심으로 개인 옷장 관리, 데일리룩 커뮤니티, 패션 중고거래를 연결하는 패션 라이프사이클 플랫폼입니다.

사용자는 옷을 구매하거나 기존 옷장을 정리할 때 사진과 정보를 등록합니다. 매일 전신 착장을 촬영하면 앱이 옷장에 등록된 옷 중 후보를 제시하고, 사용자가 확정한 옷의 착용 횟수와 마지막 착용일을 기록합니다. 착장은 선택적으로 커뮤니티에 공유할 수 있고, 오랫동안 입지 않은 옷은 기존 정보를 활용해 중고 판매 글로 전환할 수 있습니다.

현재 프로토타입의 착장 후보 추천은 사진을 실제로 분석하는 AI가 아니라 `DemoOutfitAnalyzer`가 옷장 데이터를 카테고리별로 제시하는 결정론적 Mock입니다. 실제 AI는 `OutfitAnalyzing` 인터페이스를 구현하는 방식으로 이후 교체합니다.

## 핵심 사용자 흐름

```text
옷 구매 또는 기존 옷 등록
        ↓
아침에 전신 착장 촬영
        ↓
내 옷장에서 착용한 옷 매칭
        ↓
사용자 확인 후 착용 기록 확정
        ↓
원하면 데일리룩을 커뮤니티에 공유
        ↓
착용 통계로 잘 입지 않는 옷 발견
        ↓
기존 옷 정보로 중고 판매 글 생성
```

AI는 착용 기록을 자동으로 확정하지 않습니다. 후보를 제안하고, 사용자가 최종 확인한 기록만 통계에 반영합니다.

## 제품 구성

### 개인 옷장

- 기존 옷과 새로 구매한 옷을 구분하지 않는 단일 등록 흐름
- 구매일, 가격과 사이즈는 선택 입력하고 가격이 있으면 1회 착용 비용 계산
- 사진, 카테고리, 브랜드, 구매일, 가격, 사이즈, 색상, 계절 관리
- 카메라 촬영과 사진 보관함 선택을 모두 지원
- 전면 카메라 촬영은 미리보기에서 본 거울 모습 그대로 저장
- 새 옷은 한 번에 한 벌씩 저장하며 저장 후 옷장으로 복귀
- 착장 사진은 원본 비율을 유지해 저장하고 촬영 결과는 카메라와 같은 화면 채우기 구도로 표시
- 전신 착장 사진에서 등록된 옷의 매칭 후보 제시
- 총 착용 횟수, 착용일수, 마지막 착용일 및 기간별 기록 제공
- 구매 가격을 기반으로 한 1회 착용 비용을 `45,000원`과 같은 전체 금액으로 표시
- Vision으로 등록 사진의 배경을 제거하고 투명 여백을 옷 크기에 맞춰 자른 썸네일 저장
- MY 월간 캘린더에서 날짜별 착장 조합을 확인하고 카드를 뒤집어 실제 촬영 사진 보기
- MY 착장 수정에서 포함된 옷을 추가·삭제하고 표시 순서를 드래그해 변경
- 유지, 보관, 처분 예정 상태 관리

### 패션 커뮤니티

- MY에서 실서버와 발표용 데모 데이터를 전환하고 두 데이터가 한 목록에 섞이지 않도록 분리
- 실서버에 게시물이 없을 때 첫 게시를 안내하는 전용 빈 상태
- 스크롤 중에도 유지되는 둥근 `!WEARy` 로고의 즉시 최상단 이동과 당겨서 최신화
- 실제 착장 사진 중심의 데일리룩 피드와 상세 누끼 아이템 연결
- 모자–아우터–상의–원피스–하의–신발–가방–액세서리 기본 정렬 및 게시자 순서 조정
- 좋아요, 댓글, 저장 및 팔로우
- MY에서 팔로워·팔로잉 수와 사용자 목록 확인
- 저장한 착장을 선택해 설명과 태그를 입력하는 로컬 피드 작성
- 개인 착장 기록과 공개 게시물을 명확히 분리
- 옷 또는 스타일 태그를 통한 코디 탐색

### 패션 중고거래

- 실서버 매물과 기기 전용 데모 매물을 분리하고 서버가 비었을 때 판매 시작을 안내
- 미착용 데이터에 기반한 판매 제안
- 기존 사진과 상품 정보로 판매 글 초안 자동 생성
- 판매자가 착용 횟수와 착용 사진 공개 여부 선택
- 패션 상품 중심의 목록, 상세, 관심과 채팅
- 채팅 합의 후 판매자가 상품 설명, 만날 장소, 가격과 거래 상태를 수정
- MapKit 검색 또는 지도 핀으로 만날 장소를 지정하고 매물 상세에서 지도 확인
- 판매 사진을 최대 8장까지 추가·삭제하고 상세 화면에서 좌우로 넘겨 보기
- 옷장 데이터 공개 여부를 판매자가 선택하고 공개 매물에 황금 별 인증 표시
- 직전 가격 대비 상승·하락 금액 표시
- 내 매물의 채팅 인원 확인, 판매 완료 및 게시물 삭제
- 거래 완료 시 개인 옷장의 상태와 연결

## 앱 구조

| 탭 | 역할 |
| --- | --- |
| 피드 | 데일리룩과 스타일 탐색 |
| 옷장 | 내 옷과 착용 데이터 관리 |
| 촬영 | 오늘의 착장 기록을 시작하는 핵심 행동 |
| 마켓 | 패션 중고 상품 탐색 및 판매 |
| MY | 내 착장, 게시물, 통계와 설정 |

앱 시작 시 Snow 색상의 브랜드 로딩 화면을 거칩니다. 유효한 Supabase 계정 세션이 없으면 로그인 화면을 먼저 보여 주고, 로그인 후 피드 탭으로 진입합니다. 이메일 회원가입, 이메일 또는 아이디 로그인, 본인 확인 메일을 이용한 아이디 찾기, 비밀번호 재설정과 Google·Kakao·Apple OAuth 진입 UI를 지원하며, 소셜 로그인은 각 제공자 콘솔 설정을 마친 뒤 활성화됩니다.

## 이번 주 프로토타입 범위

### 기기에서 실제로 동작하는 기능

- 로컬 옷장 등록, 조회, 수정 및 삭제
- 카메라 촬영 또는 사진 보관함에서 옷과 착장 사진 선택
- 옷 카테고리 및 구매 정보 입력
- Vision 기반 배경 제거, 투명 여백 크롭 및 누끼 썸네일 저장
- 착장 매칭 후보 확인, 교체, 추가 및 제외
- 확정 착장 저장과 착용 통계 계산
- 옷별 착장 이력 및 관리 상태 변경
- MY 월간 착장 캘린더와 일자별 상세 정보
- 로컬 피드 작성, 좋아요, 댓글, 저장, 팔로우 및 팔로워·팔로잉 목록
- 로컬 마켓 매물 생성·수정·삭제, 가격 변경과 거래 상태 관리
- 판매 사진 갤러리, 선택적 옷장 인증과 MapKit 기반 만날 장소 지정
- 이메일 회원가입, 이메일·아이디 로그인, 로그아웃과 로그인 세션 복원
- MY 프로필에서 고정 아이디, 닉네임, 신체 정보와 선택 치수 수정
- 이메일 계정의 비밀번호 변경과 재설정 메일 요청
- 가입 이메일 매직 링크로 본인 확인 후 아이디 안내
- 만료·유효하지 않은 인증 링크와 네트워크 오류별 안내

### Mock으로 제공할 기능

- 사진을 실제 분석하지 않는 카테고리 규칙 기반 옷 후보 추천
- 서버 사용자 대신 제공되는 샘플 사용자와 초기 데일리룩
- 발표용 로컬 샘플 게시물에서만 기기 안에 저장되는 소셜 상호작용
- 발표용 로컬 매물의 생성·수정·삭제와 판매 상태 변경
- 발표용 로컬 샘플에서 미리 준비된 상대방과 대화하는 채팅 화면
- 푸시 알림

### 실제 서버에 연결된 기능

- Supabase Swift SDK와 개발 프로젝트 연결
- 이메일 계정 생성, 이메일·아이디 로그인과 재실행 시 영구 세션 복원
- 가입 전 이메일·아이디·닉네임 중복 확인과 닉네임 유일성 보장
- 가입 확인 메일 재전송과 이메일 인증·비밀번호 재설정 후 앱 딥링크 복귀
- 아이디 찾기용 매직 링크 본인 확인과 앱 복귀 후 아이디 안내
- Google·Kakao·Apple OAuth 로그인 진입 및 앱 딥링크 복귀 처리
- Auth 사용자 생성 트리거를 통한 `profiles` 행 자동 생성
- 인증 사용자만 프로필을 읽고 본인 프로필만 수정할 수 있는 RLS
- 변경 불가능한 공개 아이디와 수정 가능한 닉네임·신체 치수 프로필 저장
- 게시물, 이미지 메타데이터, 아이템 스냅샷, 댓글, 좋아요, 북마크와 팔로우용 PostgreSQL 스키마
- 공개·팔로워·비공개 게시물 가시성, 작성자 수정 권한과 개인 북마크를 보호하는 RLS
- 공개 착장과 아이템 이미지를 위한 private `community-media` Storage 버킷
- 사용자·게시물 경로 소유권과 게시물 공개 범위를 함께 검사하는 Storage RLS
- Supabase의 최신 게시물, 작성자, 아이템, 댓글, 좋아요, 북마크와 팔로우 상태를 읽는 피드 Repository
- 원격 게시물을 SwiftData 캐시에 병합하고 네트워크 실패 시 기존 로컬·캐시 피드를 유지하는 오프라인 fallback
- 피드 작성과 착장 기록의 `커뮤니티에 공개`에서 게시물, 착장 사진과 누끼 아이템을 서버에 업로드하는 공통 게시 흐름
- 비공개 초안으로 업로드를 시작하고 모든 데이터 저장 후 공개하며 실패 시 중간 데이터를 보상 삭제하는 게시 안전장치
- 원격 게시물의 좋아요·댓글·북마크와 작성자 팔로우를 실제 서버에 저장하는 소셜 Repository
- MY 탭에서 실제 팔로워·팔로잉 프로필을 조회하고 로컬 샘플 관계와 함께 보여 주는 소셜 목록
- 소셜 요청 실패 시 화면 상태를 되돌리고 재시도 가능한 오류를 표시하는 optimistic update
- 게시물·댓글·좋아요·북마크·팔로우 변경을 감지해 피드를 다시 불러오는 Supabase Realtime 구독
- 생성 시각과 UUID의 복합 커서로 과거 게시물을 중복 없이 이어서 불러오는 페이지네이션
- 중고 매물·최대 8장 사진 메타데이터·관심·선택적 옷장 인증을 위한 마켓 PostgreSQL 스키마
- 판매자만 매물을 변경하고 숨긴 옷장 인증과 사용자별 관심 목록을 보호하는 마켓 RLS
- 가격 변경 시 직전 가격을 서버에서 자동 기록하고 매물 변경을 전달하는 마켓 Realtime 기반
- 매물 갤러리와 공개 인증 누끼를 위한 10MB 이미지 전용 private `market-media` Storage 버킷
- `사용자ID/매물ID/파일명` 소유권과 매물·인증 공개 상태를 함께 검사하는 마켓 Storage RLS
- Supabase의 최신 매물, 판매자, 장소, 가격 변동, 관심과 공개 인증 데이터를 읽는 마켓 Repository
- 원격 매물과 private 이미지를 SwiftData에 캐시하고 네트워크 실패 시 로컬 샘플·마지막 캐시를 유지하는 fallback
- 앱에서 매물 생성·수정·예약·판매 완료·삭제와 최대 8장 이미지 업로드를 서버에 저장하는 마켓 쓰기 Repository
- 숨김 초안으로 이미지 업로드를 시작하고 원자적 RPC로 공개하며 실패 시 중간 데이터와 파일을 보상 삭제하는 매물 게시 안전장치
- 원격 매물의 관심 등록·해제를 서버에 저장하고 실패 시 화면 상태를 되돌리는 optimistic update
- 매물·사진·인증·관심 변경을 감지해 마켓 목록을 다시 불러오는 Supabase Realtime 구독
- 매물마다 구매자 한 명당 하나의 1:1 대화방을 만들고 참여자만 메시지를 읽고 보낼 수 있는 채팅 RLS
- 구매자 채팅 작성, 판매자의 매물별 대화 목록과 실시간 메시지 수신
- 게시물·매물 신고 접수와 사용자별 비공개 신고·차단 데이터 RLS
- 차단 사용자의 원격 피드·매물·소셜 목록 제외와 MY 차단 해제 관리
- 운영자 역할 기반 신고 목록·대상 요약·처리 상태·운영 메모와 감사 로그
- 운영자가 조치 완료한 게시물·매물의 서버 숨김과 작성자 임의 복구 방지
- 신고자·콘텐츠 작성자에게 처리 결과를 전달하는 MY 앱 내 알림
- MY에서 본인 확인 문구를 거쳐 Storage 이미지, Supabase 계정·연결 데이터와 기기 로컬 데이터를 삭제하는 계정 탈퇴
- 사용자별 계정 경고·이용 제한·정지 내역 조회와 본인 제재 이의 제기 제출
- 일반 사용자의 제재 위조와 타인 내역 접근을 차단하고 운영자만 생성·심사할 수 있는 RLS/RPC

피드 화면은 MY에서 선택한 `실서버` 또는 `데모` 모드의 게시물만 표시합니다. 실서버 모드는 Supabase의 최신 원격 게시물을 15개씩 이어서 표시하며, 데이터가 없으면 첫 게시를 안내합니다. 새 서버 변경이 도착하면 현재까지 읽은 범위를 갱신하고, 다음 페이지는 기존 원격 캐시를 지우지 않고 병합합니다. 네트워크가 실패하면 마지막 서버 캐시를 유지합니다. 데모 모드는 기기 안의 발표용 샘플만 표시하고 원격 Realtime 구독을 중단합니다.

마켓 역시 `실서버`와 `데모` 매물을 한 목록에 섞지 않습니다. 실서버 모드는 Supabase의 최신 원격 매물 최대 30개를 표시하고 비어 있으면 첫 판매 등록을 안내합니다. 새 원격 매물의 작성·수정·상태 변경·삭제, 최대 8장 이미지 업로드, 관심과 상품 단위 1:1 채팅은 실제 서버에 저장되며 변경 이벤트가 오면 목록과 대화를 자동 갱신합니다. 데모 모드는 기기 안의 샘플 매물만 사용합니다.

## 로컬 실행

최초 1회 Supabase 로컬 설정을 만듭니다. publishable key는 Supabase Dashboard의 Connect 화면에서 확인하며 `service_role` 또는 secret key를 앱에 넣지 않습니다.

```bash
cp Config/Supabase.local.xcconfig.example Config/Supabase.local.xcconfig
```

`Config/Supabase.local.xcconfig`의 프로젝트 URL과 `sb_publishable_...` 키를 채운 뒤 프로젝트를 생성합니다. 로컬 설정 파일은 Git에서 제외됩니다.

```bash
xcodegen generate
open WEARy.xcodeproj
```

### Supabase Auth 설정

Supabase Dashboard의 **Authentication → URL Configuration**에서 Redirect URLs에 아래 주소를 추가합니다.

```text
weary://auth-callback
```

이 주소는 Supabase Site URL과 Redirect URLs에 함께 등록하며 이메일 확인·비밀번호 재설정·OAuth 완료 후 앱으로 돌아오는 공통 딥링크입니다. 이메일 로그인은 **Authentication → Sign In / Providers → Email**을 활성화합니다. Google·Kakao·Apple은 같은 화면에서 각 제공자를 활성화하고 해당 개발자 콘솔에서 발급한 Client ID와 Secret을 입력해야 합니다. 앱에는 publishable key만 두며 provider secret이나 `service_role` 키를 넣지 않습니다. 아이디 로그인용 이메일 조회는 배포된 `account-auth` Edge Function 내부에서만 수행합니다.

계정 데이터 규칙은 다음과 같습니다.

- 이메일과 공개 아이디를 모두 로그인 자격 증명으로 사용할 수 있으며 이메일은 다른 사용자에게 노출하지 않습니다.
- 회원가입 전에 이메일·아이디·닉네임 중복 확인을 완료해야 합니다.
- 공개 아이디(`handle`)는 영문 소문자·숫자·`.`·`_` 조합 3–20자이며 최초 설정 후 변경할 수 없습니다.
- 닉네임은 대소문자를 무시해 중복을 허용하지 않으며 수정 가능하고 피드 작성자명과 새 판매 글의 판매자명으로 사용합니다.
- 비밀번호는 `profiles`에 저장하지 않고 Supabase Auth에서만 관리합니다.
- 신체 정보와 추가 치수는 본인만 읽고 수정할 수 있는 별도 테이블에 저장하며, 현재는 추천·광고에 사용하지 않습니다.

명령행 빌드는 다음과 같이 검증할 수 있습니다.

```bash
xcodebuild -project WEARy.xcodeproj \
  -scheme WEARy \
  -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO \
  build
```

전체 단위·UI 테스트는 다음과 같이 실행합니다.

```bash
xcodebuild -project WEARy.xcodeproj \
  -scheme WEARy \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  CODE_SIGNING_ALLOWED=NO \
  test
```

Supabase 커뮤니티 권한은 연결된 개발 프로젝트를 대상으로 다음처럼 검증합니다. 테스트 게시물과 반응은 종료 시 삭제되지만 익명 Auth 테스트 사용자 두 명은 남습니다.

```bash
scripts/verify_supabase_community.sh
scripts/verify_supabase_storage.sh
scripts/verify_supabase_profiles.sh
scripts/verify_supabase_market.sh
scripts/verify_supabase_market_storage.sh
```

실제 Swift Repository의 커뮤니티 게시·이미지 업로드·소셜 상호작용·피드 재조회·커서 페이지네이션·Realtime 이벤트와 마켓 매물·private 이미지·관심·채팅·신고·차단·계정 탈퇴 왕복은 다음 선택형 통합 테스트로 검증합니다. 독립된 사용자 A/B 세션으로 게시물·팔로우·댓글·매물·양방향 채팅까지 이어지는 전체 공유 시나리오도 포함합니다. 생성한 게시물, 매물, 관계, 대화, 신고와 Storage 파일은 테스트 종료 시 삭제되며, 계정 탈퇴 검증은 별도의 일회용 사용자를 생성해 스스로 삭제합니다.

```bash
RUN_SUPABASE_INTEGRATION=1 xcodebuild -project WEARy.xcodeproj \
  -scheme WEARy \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -only-testing:WEARyTests/SupabaseIntegrationTests \
  test
```
